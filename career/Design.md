# 석사 학위 논문 설계 원칙

## 0. 목적

이 문서는 dry 연구 기반 석사 학위 논문의 주제를 고르고, 범위를 통제하고,
완료 여부를 판단하기 위한 기준이다. 특정 주제, 데이터셋, 모델과 구현 계획은 별도의
상세 설계 문서에서 관리한다.

## Ⅰ. 핵심 가치

### 1. 실제로 존재하는 문제에서 시작한다

논문을 쓰기 위해 문제를 만들지 않는다. 기존 분석이나 사용 과정에서 반복해서
발생했고, 결과의 해석이나 다음 의사결정을 방해하는 문제를 선택한다.

### 2. 방법은 목적이 아니라 검증 가능한 해결 수단이다

연구 방법을 먼저 정하고 적용할 문제를 찾지 않는다. 단순 규칙으로 충분한 문제를
복잡한 모델로 포장하지 않는다. 복잡도는 더 나은 일반화, 반복 작업 감소 또는 기존
방법으로 표현할 수 없는 관계를 보여줄 때만 정당화한다.

### 3. 완주 가능성도 연구 가치다

석사 논문의 목표는 가장 복잡한 연구가 아니라 제한된 기간 안에 방어 가능한 질문에
답하는 것이다. 새로운 알고리즘 자체뿐 아니라 문제 정의, 데이터 구성, feature 설계,
비교 실험, 실패 원인 규명과 재현 가능한 구현도 기여가 될 수 있다.

### 4. 주장보다 증거를 작게 유지한다

검증한 데이터, 분류 수준과 조건 밖으로 주장을 확장하지 않는다. 서로 다른 측정
방법의 일치도를 측정한 결과를 생물학적 진실이나 임상 성능으로 바꾸어 말하지 않는다.

### 5. 재현되지 않는 성능은 결과가 아니다

같은 manifest, code, database, seed와 실행 환경으로 동일한 feature와 평가 결과를
만들 수 있어야 한다. 공개할 수 없는 데이터는 비식별 파생값과 schema, 공개 데이터
기반 재현 경로로 보완한다.

## Ⅱ. 데이터 원칙

### 6. 표본 수는 독립 단위로 센다

행 수를 표본 수로 부르지 않는다. 동일한 원천에서 파생된 여러 행은 서로 독립이
아니다. split과 통계 비교는 실제 독립 단위를 보존한다.

### 7. 레이블이 생성된 과정을 기록한다

레이블의 이름보다 누가, 무엇으로, 어떤 조건에서 측정했는지가 중요하다. 관측 과정이
곧 편향이다. 알고리즘의 출력을 그대로 자연의 정답으로 사용하지 않는다.

### 8. 음성 레이블을 정의한다

음성 사례가 어디에서 왔는지 답하지 못하면 태스크도 정의되지 않은 것이다. 무작위로
고른 음성은 실제 문제보다 샘플링 방식을 학습시킬 수 있다.

### 9. 시뮬레이션의 역할을 제한한다

시뮬레이션은 학습, 통제 실험과 실패 조건 생성에 사용한다. 시뮬레이터로 학습하고 같은
시뮬레이터로만 평가한 결과를 현실 데이터의 성능으로 주장하지 않는다. 최종 결과에는
학습 과정과 독립된 평가 지점을 둔다.

### 10. 데이터베이스와 전처리도 실험 조건이다

reference database, taxonomy, 전처리 pipeline과 cutoff가 바뀌면 입력 데이터의 의미도
바뀐다. 이들의 버전과 checksum을 기록하고, 데이터가 지원하지 않는 사례와 모델 실패를
구분한다.

## Ⅲ. 평가 원칙

### 11. 일반화하려는 축을 따라 분할한다

row-level random split을 기본값으로 사용하지 않는다. 새 개체, 집단, 시점, 계통 또는
데이터 수집 환경 중 무엇에 일반화하려는지 먼저 정하고 그 축을 따라 나눈다.

석사 논문에서 가능한 모든 외부 환경을 검증할 필요는 없다. 대신 고정된 validation,
학습에 사용하지 않은 test와 최소 하나의 현실 데이터 평가 지점을 확보한다.

### 12. 가장 단순한 baseline을 먼저 고정한다

규칙, 최근접 이웃, 기존 도구 또는 단순 통계 모델 중 문제에 맞는 baseline을 먼저
실행한다. 이 결과를 본 뒤 baseline이나 metric을 교체해 승리 조건을 만들지 않는다.

### 13. 지표는 실제 의사결정의 형태를 따른다

분류, 순위화, 후보 선택, 수치 추정 중 실제 사용 방식에 맞는 지표를 고른다. 평균 성능
하나만 보고하지 않고 중요한 오류의 비용을 직접 나타내는 지표를 포함한다.

### 14. 성능을 거리와 조건에 따라 나누어 본다

전체 평균은 가까운 사례가 만든 숫자일 수 있다. 학습 데이터와의 거리, 데이터 품질,
subgroup 또는 입력 난이도에 따라 성능을 나누어 보고한다. 작은 subgroup의 결과를
일반적인 결론으로 확대하지 않는다.

### 15. 필요한 만큼만 불확실성을 보고한다

독립 단위를 보존한 confidence interval이면 석사 논문에 충분할 수 있다. nested CV,
형식적 coverage 보장과 복잡한 다중검정은 연구 질문에 직접 필요할 때만 추가한다.

## Ⅳ. 모델링 원칙

### 16. 모델 입력은 설명할 수 있어야 한다

feature가 무엇을 측정하며 왜 문제 해결에 도움이 되는지 설명한다. 결과에 직접 연결할
수 없는 feature를 성능이 오른다는 이유만으로 계속 추가하지 않는다.

### 17. 모델 수를 늘려 결과를 고르지 않는다

단순 baseline과 하나의 주 모델을 먼저 정한다. 여러 알고리즘을 순회한 뒤 가장 높은
숫자만 보고하지 않는다. 추가 모델은 기존 가설과 다른 질문에 답할 때만 사용한다.

### 18. 데이터 규모에 맞는 모델을 쓴다

큰 모델의 성질은 데이터 규모에 딸려 온다. 독립 표본이 작으면 모델 복잡도를 줄이고,
규제와 분할을 더 보수적으로 설계한다. 모델 이름보다 유효 표본 수를 먼저 본다.

### 19. Feature 기여를 분리한다

가장 단순한 feature 집합과 전체 feature 집합을 비교한다. 전체 feature가 개선되지 않으면
feature 설계의 실패 또는 단순한 방법으로 충분한 문제라는 결론을 기록한다.

## Ⅴ. 연구 설계 원칙

### 20. 가장 싼 반증을 가장 먼저 실행한다

6개월짜리 pipeline을 만들기 전에 2주짜리 실험으로 핵심 전제가 존재하는지 확인한다.
첫 실험 비용이 2주를 넘기면 더 작게 나눈다. 신호가 노이즈와 구분되지 않으면 모델을
키우기 전에 주제를 중단하거나 바꾼다.

### 21. 음성 결과로도 논문이 되는 주제를 고른다

성공과 실패의 결론을 모두 미리 쓴다.

- 성공하면 무엇을 새로 할 수 있는가?
- 실패하면 기존 방법의 어떤 한계나 데이터 조건을 확인하는가?

실패 쪽에 남는 결과가 없다면 아직 논문 주제가 아니다.

### 22. 사전 계획은 짧게 고정한다

모델 학습 전에 다음을 문서로 남긴다.

- 데이터와 제외 기준
- split 단위
- feature schema
- baseline과 주 모델
- primary metric
- 최종 test
- 성공과 중단 조건

완전한 임상시험 수준의 pre-registration은 요구하지 않지만, test 결과를 본 뒤 설계를
바꾸는 일을 확인할 수 있을 정도의 기록은 남긴다.

### 23. 논문과 Engineering을 분리한다

학위 논문의 완료 조건은 연구 질문에 답하는 데이터, 모델, 평가와 재현 가능한 실행
경로다. 서빙, 모니터링과 운영 배포는 논문의 주장에 필요할 때만 포함하고, 그렇지 않으면
후속 프로젝트로 분리한다.

## Ⅵ. 설계 게이트

1. 실제 문제와 사용자를 한 문장으로 설명한다.
2. 목표 기여와 석사 과정 안의 완료 가능성을 따로 평가한다.
3. 선행연구와 가장 단순한 baseline을 확인한다.
4. label, 음성 사례, split 단위와 primary metric을 고정한다.
5. 성공과 실패의 결론을 모두 쓴다.
6. 2주짜리 반증 실험을 통과한 뒤 본 프로젝트로 승격한다.
7. 독립 test와 재현 명령을 확인한 뒤 논문 결과를 고정한다.

누수, 불명확한 레이블, baseline 부재와 재현 불가능성은 완화하지 않는다. 새 알고리즘,
다수의 외부 데이터, 가장 복잡한 모델과 운영 배포는 석사 논문의 필수 조건이 아니다.
